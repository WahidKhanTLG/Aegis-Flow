# Aegis Flow user quick start

**Prepared:** November 9, 2026. Labels below match the inspected component source. Your
administrator must confirm the available Lightning app, permissions and supported surfaces.
This guide does not establish that a customer's environment has been accepted.

## When to use Aegis

Use Aegis when a supported process reports a diagnostic reference or an alert, or when you
need to describe a problem through **Get Help**. Not every error from Salesforce's native
Save or Lead Convert appears automatically. Report the task, what you expected, and the
safe reference shown; do not repeatedly submit the same business operation to force a result.

## Open and review an alert

1. Open your configured Lightning app and its Aegis alerts utility. If the app has no utility,
   ask the administrator which supported page or app to use.
2. Review the alert and choose **View details** when available. Read the diagnosis and next step.
3. If saved alerts appear out of date, choose **Refresh alerts** once. A streaming warning can
   coexist with working saved alerts. A refresh does not retry a business operation.
4. Keep the diagnostic/correlation reference when reporting the issue. Give the task and time
   to support through the approved channel; avoid copying sensitive technical payloads.

You should see only information allowed by your role and record access. A denied or missing
foreign record is not a reason to request broad administrator access.

## Ask for help without an alert

Open **Get Help**. In the standalone Get Help panel, enter **Describe the task or issue** and,
if useful, **Related diagnostic reference (optional)**. Choose **Create diagnostic session**,
then **Analyze captured context** when available. A session records your description; it does
not automatically repair or retry the original process. The monitor also provides a separate
**Capture Screen Issue** path with **What went wrong?** and **Submit**.

Describe the operation and safe reproduction steps. Do not paste passwords, tokens, payment
information or unnecessary personal data. If no reliable correction is available, retain the
reference and contact support or use the configured governed report option.

## Review a proposed action

A displayed recommendation is guidance. A correction or retry runs only when the action is
registered, your access permits it, the required feature is enabled and you explicitly confirm.
Read the affected record/field/action before confirming. Do not repeat a failed or uncertain
operation until support has checked its audit and business outcome.

Aegis cannot approve an arbitrary customer business repair. If an action is unavailable or
denied, ask support to review the process and permissions; do not change the target or use
another identity to bypass the denial.

## Send a governed report

In Get Help or Diagnostic Assistant, review the configured recipient/channel and evidence scope. Check
**I confirm sending this diagnostic evidence to the configured technical team.** only when
you intend to send it, then choose **Send governed report**. Other configured surfaces may
present an escalation confirmation dialog. A report can send a real message or create a Case.

After a report is created, that session keeps its Send control disabled. Start a new session
for a different issue. A failed request requires fresh confirmation; check the same reference
with support before trying again.

If the outcome is pending, failed or uncertain, give support the same reference. Do not send
again to find out whether the first request worked. The support team must reconcile delivery.

## Dismiss and follow up

Choose **Dismiss** for an alert you no longer need to see. Dismissal hides that notice; it does
not prove the business problem is resolved or delete diagnostic history. If the issue persists,
contact the configured support team using the reference and describe what remains blocked.

The administrator must confirm mobile support for the chosen surface. Desktop utility bars
must not be assumed available in the native Salesforce mobile app. Supported browsers, small
screen behavior, keyboard operation and accessibility are accepted through the separate test plan.

For support-team procedures and current limits, see [Operating handoff](OPERATIONS_HANDOFF.md).
